# راهنمای مشارکت

## نام‌گذاری برنچ‌ها

| نوع       | الگو                | مثال                    |
| --------- | ------------------- | ----------------------- |
| قابلیت    | `feature/<slug>`    | `feature/search-bar`    |
| رفع باگ   | `fix/<slug>`        | `fix/price-formatting`  |
| زیرساخت   | `chore/<slug>`      | `chore/test-harness`    |

## قرارداد کامیت‌ها

از [Conventional Commits](https://www.conventionalcommits.org/) استفاده می‌کنیم:

```
<type>(<scope>): <subject>

<body — چرا این تغییر لازم بود>
```

- `feat` قابلیت جدید، `fix` رفع باگ، `test` تست، `docs` مستندات، `chore` زیرساخت.
- هر کامیت باید در یک قدم منطقی، تست‌ها را سبز نگه دارد.
- یک کامیت = یک تصمیم. اگر پیام کامیت به «و» نیاز دارد، احتمالاً باید دو کامیت باشد.

## پول‌ریکوئست

1. برنچ را از `main` بسازید.
2. حداقل سه کامیت معنادار بسازید (کد + تست + در صورت نیاز استایل).
3. PR را با توضیح «چه چیزی، چرا، چگونه تست شد» باز کنید.
4. پیش از ادغام باید تست‌ها سبز و ریویو تأیید شده باشد.
